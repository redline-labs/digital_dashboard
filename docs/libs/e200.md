# e200

## Overview

The Freescale/NXP e200 core as the MPC55xx carry it (e200z6): 32-bit Book E
with isel and wait, the MAS-register MMU (TLB1), the interrupts with their
save/restore registers, the timebase and decrementer, and the SPE's scalar
single-precision floating point. With it come the machine that runs it on a
32-bit physical bus, a disassembler, and an assembler for programs written in
C++ -- so the tests, and the bare images an SoC's tests boot, need no target
toolchain.

Three engines run the same core under one contract: an interpreter, a block
engine that runs from a decode cache, and a JIT that translates blocks to
AArch64 through asmjit. On a host with no JIT backend (x86-64, for now) the JIT
engine runs the block engine and says so once.

It is a CPU, not a microcontroller: the on-chip modules of a particular MPC55xx
belong to the SoC that maps them, and the wiring they share is [emu](emu.html).

## Using it

Link the CMake target `e200`. Map memories and devices, set up the MMU (or
leave the reset state: only the 4 KB boot page at 0xFFFFF000 is mapped), and
call `Machine::run_until`. The engine is `MachineConfig::engine`; time is the
core clock, one tick per core cycle and one cycle per instruction.

## Behaviour worth knowing

The engines must agree instruction by instruction, registers, memory and cycle
count included. A pc watch makes the JIT engine interpret while it is set.

Translation goes through a software TLB in front of the MMU: 256 entries per
access kind, one set per MSR mode. Device pages never enter it, and neither do
writes to pages that hold decoded code, so a program that rewrites its own code
(a kernel loading an application into RAM) runs correctly: the write drops the
decoded and translated code for that page first.

The SPE arithmetic is the embedded kind, not IEEE 754: denormal operands are
zero, infinite or NaN operands are invalid and give the largest finite value,
overflow saturates and underflow is zero. The floating-point exception
interrupts are not taken.

Undefined results are the e200's: `divw` and `divwu` saturate on overflow and on
division by zero.

## Tests

| Target | Proves |
| --- | --- |
| `e200_test_core` | The instructions with their XER and CR effects, interrupts and privilege, the decrementer, the MMU and its faults, the SPE, the disassembler, and the machine (bus, devices, interrupt inputs, wait, self-modifying code, the software TLB) on every engine. |
| `e200_test_engine_diff_block`, `e200_test_engine_diff_jit` | Random programs give identical state on the interpreter and on the other engine at random points (slow). |
| `e200_test_engine_diff_catches_broken` | The same check against a run corrupted on purpose must fail. |

`e200_engine_diff --bench` reports each engine's speed on a small loop.
